## 1. 代码扩展规范

### 1.1 文件命名规范

参照现有代码的模块结构，新模块应遵循以下文件命名规范：

```
新模块目录/
├── graph.py        # LangGraph 工作流定义（节点、边、图编译）
├── states.py       # TypedDict 状态定义
├── prompts.py      # 所有 Prompt 模板（SystemPrompt + UserPrompt）
├── llm.py          # LLM 工厂函数（复用或扩展 financial/llm.py）
├── utils.py        # 工具函数（文件操作、数据处理等）
├── schemas.py      # Pydantic 模型（用于结构化输出）
└── tools/          # 工具目录（可选，如有外部 API 调用）
    ├── tool_a.py
    └── tool_b.py
```

| 文件 | 职责 | 现有示例 |
|------|------|---------|
| `graph.py` | 工作流主文件，定义节点函数 + 图结构 | `07.CodeAct/codeact/graph.py` |
| `states.py` | 状态数据结构定义 | `21~26.financial/states.py` |

**`news_sentiment_agent/tools/news_search.py`：**

```python
from langchain_core.tools import tool
from langchain_community.utilities import SearxSearchWrapper
import os
from dotenv import load_dotenv

load_dotenv()

@tool
def search_company_news(company_name: str, time_range: str = "最近一个月") -> str:
    """搜索指定公司的最新新闻和舆情信息。
    
    Args:
        company_name: 公司名称，如 "贵州茅台"
        time_range: 时间范围，如 "最近一个月"、"最近一年"
        
    Returns:
        新闻搜索结果的汇总文本
    """
    # 使用 SearXNG 搜索（与项目中 18.deepresearch 保持一致）
    engines = ["baidu", "sogou", "quark"]
    search = SearxSearchWrapper(
        searx_host=os.environ.get("SEARXNG_HOST", "http://localhost:8080/"),
    )
    search_ret = search.results(
        f"{company_name} 最新新闻 {time_range}",
        num_results=5,
        time_range="year",
        engines=engines,
    )
    
    # 格式化结果
    news_text = []
    for r in search_ret:
        title = r.get("title", "无标题")
        snippet = r.get("snippet", "无简介")
        link = r.get("link", "无链接")
        news_text.append(f"标题：{title}\n内容：{snippet}\n来源：{link}")
    
    return "\n\n".join(news_text)
```

> 💡 **初学者提示：** 本项目统一使用 SearXNG 搜索引擎（通过 `langchain-community` 中的 `SearxSearchWrapper`），需要自行部署 SearXNG 服务或使用已有的服务地址。11.websearch 模块额外使用了 BochaSearch API 作为替代方案。

```python
from langchain_core.messages import HumanMessage
from langgraph.prebuilt import create_react_agent
from langgraph.graph import StateGraph, START, END
import sys
import os

# 将父目录加入路径，以便导入 llm.py
sys.path.append(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from llm import DeepSeek
from .tools.news_search import search_company_news
from .prompts import news_search_prompt, news_analysis_system

class NewsSentimentAgent:
    """新闻舆情数据收集 Agent"""
    
    def __init__(self):
        self.llm = DeepSeek()
        self.tools = [search_company_news]
        self.agent = create_react_agent(self.llm, self.tools)
    
    def run(self, stock_code: str, stock_name: str, year: str) -> str:
        """运行舆情收集
        
        Args:
            stock_code: 股票代码
            stock_name: 公司名称

        prompt = news_search_prompt.format(
            company_name=stock_name,
            stock_code=stock_code,
            year=year
        )
        
        result = self.agent.invoke({
            "messages": [HumanMessage(content=prompt)]
        })
        
        last_message = result["messages"][-1]
        return last_message.content


if __name__ == "__main__":
```

## 3. 模块间交互方式

### 3.1 OverallState 作为全局共享状态的设计模式

`OverallState` 是整个工作流的"数据总线"，所有节点通过它共享数据：

```
节点 A（写入）               节点 B（读取）
   │                              │
   ├── return {"field_x": value}  │
   │                              │
   └──────────────────────────────▼
                         state["field_x"]
```

**设计原则：**

```python
# ✅ 好的实践：节点只修改它负责的字段
def node_a(state: OverallState) -> dict:
    result = process(state["input"])
    return {"output_a": result}  # 只返回自己写入的字段

# ❌ 避免：直接修改整个 state（除非必要）
def bad_node(state: OverallState) -> OverallState:
    state["output_a"] = "value"
    state["output_b"] = "value"
    return state  # 这样会导致状态合并逻辑复杂
```

### 3.2 子 Agent 返回值如何被主工作流消费

金融研报系统中所有子 Agent 都遵循相同的调用接口：

```python
# 统一的子 Agent 调用模式
class SomeAgent:
    def run(self, *args) -> str:
        """运行 Agent，返回字符串结果"""
        result = self.agent.invoke({"messages": [HumanMessage(content=prompt)]})
        last_message = result["messages"][-1]
        return last_message.content

# 主工作流的节点函数调用子 Agent
def get_something(state: OverallState) -> dict:
    agent = SomeAgent()
    result = agent.run(state["stock_code"], state["stock_name"])
    
    # 1. 长期记忆：保存为文件
    save_markdown(result, "某数据.md")
    
    # 2. 短期记忆：更新 State
    return {"some_data": result}
```

### 3.3 LangGraph `Send` 用于并行执行

当需要对多个目标（如多个股票、多个查询）并行执行相同操作时，使用 `Send`：

```python
from langgraph.types import Send

# 示例：并行获取多家公司的数据
def fan_out_to_companies(state: OverallState):
    """将任务分发给多个并行工作流"""
    companies = [
        {"stock_code": state["stock_code"], "stock_name": state["stock_name"]}
    ]
    
    # 添加竞争对手
    for c in state["competitor_info"].competitors:
        companies.append({
            "stock_code": c.stock_code,
            "stock_name": c.stock_name
        })
    
    # 并行发送给 process_single_company 节点
    return [
        Send("process_single_company", company)
        for company in companies
    ]

# 目标节点：处理单个公司
def process_single_company(state: dict) -> dict:
    stock_code = state["stock_code"]
    # 处理逻辑...
    return {"result": f"{stock_code} 处理完成"}

# 图结构
builder.add_conditional_edges("some_node", fan_out_to_companies, ["process_single_company"])
builder.add_edge("process_single_company", "collect_results")
```

> 💡 **初学者提示：** 使用 `Send` 并行执行时，所有子任务完成后，结果会通过 `Annotated[list, operator.add]` 类型的 State 字段自动合并。需要在 State 中定义相应的聚合字段。

### 4.1 以 MCP 工具为例（参照 04.linux-exec-mcp / 05.linux-exec-mcp）

MCP（Model Context Protocol）允许通过标准协议调用外部工具服务。

```python
# my_mcp_server.py
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("数据处理服务")

@mcp.tool()
async def analyze_csv(file_path: str) -> str:
    """分析指定的 CSV 文件，返回统计摘要。
    
    Args:
        file_path: CSV 文件的绝对路径
        
    Returns:
        包含行数、列数、数值统计的摘要文本
    """
    import pandas as pd
    df = pd.read_csv(file_path)
    
    summary = f"文件：{file_path}\n"
    summary += f"形状：{df.shape[0]} 行 × {df.shape[1]} 列\n"
    summary += f"列名：{', '.join(df.columns.tolist())}\n"
    summary += f"\n数值统计：\n{df.describe().to_string()}"
    
    return summary

# 启动服务器
if __name__ == "__main__":
    mcp.run(transport="streamable-http", host="0.0.0.0", port=8000)
```

### 4.2 以函数工具为例（参照 06.ReAct/functioncalling）

对于简单的本地功能，直接使用 `@tool` 装饰器更方便：

```python
from langchain_core.tools import tool
from typing import Optional

@tool
def calculate_pe_ratio(
    stock_price: float, 
    earnings_per_share: float,
    company_name: Optional[str] = None
) -> str:
    """计算股票的市盈率（P/E Ratio）。
    
    市盈率 = 股价 / 每股收益，用于评估股票估值水平。
    市盈率越低，通常意味着股票越便宜（相对历史水平）。
    
    Args:
        stock_price: 当前股票价格（元/股）
        earnings_per_share: 最近12个月每股净利润（元/股）
        company_name: 公司名称（可选，用于格式化输出）
        
    Returns:
        包含市盈率计算结果和简单解读的字符串
    """
    if earnings_per_share <= 0:
        return f"{'[' + company_name + '] ' if company_name else ''}无法计算市盈率：每股收益为负或零（亏损公司）"
    
    pe_ratio = stock_price / earnings_per_share
    
    # 简单的估值判断
    if pe_ratio < 15:
        assessment = "低估值（市盈率 < 15）"
    elif pe_ratio < 30:
        assessment = "正常估值（市盈率 15-30）"
    else:
        assessment = "高估值（市盈率 > 30）"
    
    company_str = f"[{company_name}] " if company_name else ""
    return f"{company_str}市盈率 = {pe_ratio:.2f}，{assessment}"
```

## 6. 性能优化建议

### 6.1 并行节点：用 `Send` 并行化数据收集

**当前串行模式（慢）：**

```python
# 串行：一个接一个处理竞争对手
for competitor in competitors:
    agent.run(competitor.stock_code, ...)  # 总耗时 = N * 单次耗时
```

**优化为并行模式（快）：**

```python
from langgraph.types import Send
from typing import Annotated
import operator

# 在 State 中添加聚合字段
class OverallState(TypedDict):
    # ...现有字段...
    parallel_results: Annotated[list, operator.add]  # 并行结果自动合并

# 扇出节点：将任务分发给并行节点
def fan_out_data_collection(state: OverallState):
    targets = [{"stock_code": state["stock_code"], "stock_name": state["stock_name"], "year": y}
               for y in state["year"]]
    
    for competitor in state["competitor_info"].competitors:
        for year in state["year"]:
            targets.append({"stock_code": competitor.stock_code, "stock_name": competitor.stock_name, "year": year})
    
    return [Send("collect_single", target) for target in targets]

# 并行节点：处理单个目标
def collect_single(state: dict) -> dict:
    result = DataCollectionAgent().run(state["stock_code"], state["stock_name"], "A股", state["year"])
    return {"parallel_results": [f"{state['stock_code']}_{state['year']}: 完成"]}

builder.add_conditional_edges("get_competitor_info", fan_out_data_collection, ["collect_single"])
builder.add_edge("collect_single", "merge_results")
```

### 6.2 缓存 LLM 调用

对于相同输入可能多次被请求的场景，使用 LangChain 的内置缓存：

```python
from langchain.globals import set_llm_cache
from langchain.cache import InMemoryCache, SQLiteCache

# 方案一：内存缓存（进程内有效）
set_llm_cache(InMemoryCache())

# 方案二：SQLite 缓存（跨进程有效，适合调试开发）
set_llm_cache(SQLiteCache(database_path=".langchain_cache.db"))

# 之后所有 LLM 调用，相同输入自动返回缓存结果（不消耗 API 配额）
llm = DeepSeek()
result1 = llm.invoke("贵州茅台的竞争对手是？")  # 第一次：调用 API
result2 = llm.invoke("贵州茅台的竞争对手是？")  # 第二次：直接返回缓存
```

> ⚠️ **注意：** 缓存适合开发调试阶段，生产环境中需要谨慎使用，因为缓存的旧结果可能不再准确（如股价数据）。
